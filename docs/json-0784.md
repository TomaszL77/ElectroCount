# 0.7.8.4 — dane liczbowe i wzorce z rzutów

Komunikat `Object of type int64 is not JSON serializable` oznacza, że wynik obliczeń NumPy został przekazany do standardowego zapisu JSON bez konwersji. Wspólna funkcja na granicach procesu analizy, renderowania, panelu uczenia, cache, modelu i projektu zamienia scalary NumPy na zwykłe liczby/wartości logiczne oraz tablice na listy. Nie zastępuje liczb tekstem i nadal zgłasza nieobsługiwane obiekty.

Odczyt wzorca nie blokuje się już przez przyciętą ramkę otaczającą cały arkusz, jeśli jej rzeczywiście namalowana geometria nie przecina zaznaczenia. Przycięte fragmenty dotykające wycinka nadal wymagają pełnego wzorca rastrowego. Geometria pomocnicza przyciętych ścieżek ma ograniczony budżet pamięci.

Dodano jawny tryb **Wzorzec bez oznaczenia: sam kształt** w Ustawieniach i menu grupy. Umożliwia analizę pełnej geometrii bez wymagania kodu tekstowego i bez wymuszania koloru. Jest przydatny dla szarych kopii rysunków. Tryb kształtu i koloru oraz pełna analiza oznaczeń pozostają osobnymi wyborami. Elementy wewnętrzne i wypełnienie nadal są sprawdzane: pustego i pełnego koła nie wolno utożsamiać. Nazwa grupy nie zastępuje poprawnej definicji typu.

Przy różnych sposobach kodowania legendy i rzutu należy użyć pełnego, czytelnego przykładu na rzucie. Brak potwierdzonego trafienia dla danego wzorca nie dowodzi nieobecności aparatu. Wzorce z legendy i pojedyncze przykłady nie potwierdzają skuteczności modelu dla danej rodziny na całym dokumencie.

Do aktywnych sprawdzeń dodano przekazanie i zapis wyników zawierających NumPy int64, float32, bool i tablice oraz zaznaczenie czystego symbolu wewnątrz przyciętej ramki. Prywatne PDF-y, modele i dane użytkownika nie są częścią repozytorium.
